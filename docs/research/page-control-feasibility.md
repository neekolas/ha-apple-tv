# Interacting with a page mirrored to Apple TV

**Keep tvpipe in charge of Chromium.** The bridge already connects Playwright to that browser and uses it to inspect the presented document. Two MCP tools can expose snapshots and single input actions. The main engineering work is proving which document is on screen when an action arrives. Recorded MP4 playback needs a separate response because its pixels have already been encoded.

Source references below use bridge checkout `02770e95`. Bridge paths beginning with `present/`, `tools/`, or a Python filename are relative to `app/atv_bridge_app/`. tvpipe references use tag `v0.2.0`, commit `c2456d29`. The installer pins that release and its aarch64 binary digest (`app/build/install-tvpipe.sh:3–14`). This is a source review. Interaction and snapshot timings on a Green remain unmeasured.

## 1. Connecting to the captured tab

- **The existing path works at the right layer.** `TvpipeSender.start()` allocates a temporary profile. Its child command is `tvpipe --machine share <url> … --profile <dir>`. `browser_page()` reads the port from that directory, calls `chromium.connect_over_cdp()` on loopback and caches a page from an existing context. The sender already uses that page for top-level navigation and frame inspection. See `present/tvpipe.py:73–80,95–162,220–241`. [Playwright connection contract](https://playwright.dev/python/docs/api/class-browsertype#browser-type-connect-over-cdp)
- **The endpoint comes from tvpipe.** For Chromium URL sharing it supplies `--headless=new`, `--user-data-dir=<profile>`, `--remote-debugging-port=0` and the tab-capture flag. Chromium picks the port. tvpipe clears any old marker, reads the port and browser WebSocket path from `DevToolsActivePort`, then connects to loopback. This is TCP/WebSocket. The bridge's stdin pipe carries the tvpipe machine protocol, including stop. [launch.rs:623–656](https://github.com/mitsuhiko/tvpipe/blob/v0.2.0/crates/tvpipe/src/browser/launch.rs#L623-L656) · [launch.rs:745–755](https://github.com/mitsuhiko/tvpipe/blob/v0.2.0/crates/tvpipe/src/browser/launch.rs#L745-L755) · [launch.rs:807–819](https://github.com/mitsuhiko/tvpipe/blob/v0.2.0/crates/tvpipe/src/browser/launch.rs#L807-L819) · `present/tvpipe.py:18–29,237–242`.
- **No wrapper change is needed.** Docker sets `TVPIPE_BROWSER` to the wrapper. The wrapper executes Debian Chromium and forwards every incoming argument. `--browser` and the environment variable select an executable. The v0.2.0 `share URL` CLI has no existing-target or CDP-endpoint option. Starting Chromium in the app would mean maintaining a different capture integration, such as the browser share client, including its media and restart lifecycle. See `app/Dockerfile:3–11`, `app/build/chromium-wrapper:1–2`. [cli.rs:429–503](https://github.com/mitsuhiko/tvpipe/blob/v0.2.0/crates/tvpipe-cli/src/cli.rs#L429-L503)
- **Tighten page selection for input.** Today the bridge takes the first matching URL or, after a redirect, the only HTTP(S) page. A popup can duplicate a URL or outlive its opener. At show time bind the unique expected stage page in this sender's private browser, before any direct navigation. Retain its target identity across `goto()`. Fail closed on ambiguity, target loss or a changed browser WebSocket path. Use both marker lines on reconnect so a recycled port cannot silently select another browser. tvpipe can restart Chromium without changing the tvpipe PID. Rebind only after verifying a fresh presentation, never by picking the last remaining tab. See `present/tvpipe.py:108–129,184–205,314–339`. [headless.rs:430–456](https://github.com/mitsuhiko/tvpipe/blob/v0.2.0/crates/tvpipe/src/browser/headless.rs#L430-L456) · [headless.rs:702–729](https://github.com/mitsuhiko/tvpipe/blob/v0.2.0/crates/tvpipe/src/browser/headless.rs#L702-L729)

## 2. Selecting the document and delivering input

| What is showing | Where the tools operate |
| --- | --- |
| Inline HTML, files, bundle, or frameable live URL | Resolve the routed TV's `stage.origin + "/stage"` and its committed, visible iframe. The app already resolves `iframe[data-page-id=…]` to a Playwright `Frame`. Add the revision to the iframe and ready acknowledgment. Require ready, matching revision, one matching visible owner and a committed document. See `stage.py:168–181,233–245`, `data/stage.html:32–61`, `present/tvpipe.py:131–162`, `fleet.py:466–482`. |
| Live URL displayed directly | The bridge tries the stage first, then navigates the same captured tab on a framing refusal or stage timeout. Use its main frame only when `stage.direct_browser` is the active mirror. Record the approved committed destination at show time. Recheck on navigation. Never infer direct mode from a missing iframe. See `live.py:27–48,97–122`, `tools/__init__.py:432–475`, `present/tvpipe.py:95–105`. |
| MP4 or auto fallback to MP4 | Return `page_not_live`. `StageRenderer` owns a Playwright page, but `PlayUrlSender` records it to a file and the TV fetches that recording. Existing `tv_update` renders again. Check the *active* sender on every call because auto recovery can switch it in the background. See `present/render.py:36–73`, `present/play_url.py:61–69,98–117`, `present/sender.py:63–76,98–111`, `tools/__init__.py:505–515`. |

**Cross-origin input is feasible.** Use a frame locator or the resolved `Frame` to find a unique control by role and exact accessible name. Playwright attaches to out-of-process iframes (OOPIFs), checks hit targets through the iframe ancestry and sends Chromium input. A locator click accounts for the iframe offset. Targeted fill or press establishes focus inside the content. A bare page keyboard call goes to whichever document holds focus. For wheel input, first hover a verified point within the content and confirm what is under the pointer. An easier first implementation scrolls the resolved document or named scroll container with a fixed helper. [Frame locators](https://playwright.dev/python/docs/frames) · [crPage.ts:696–716](https://github.com/microsoft/playwright/blob/v1.51.1/packages/playwright-core/src/server/chromium/crPage.ts#L696-L716) · [dom.ts:890–923](https://github.com/microsoft/playwright/blob/v1.51.1/packages/playwright-core/src/server/dom.ts#L890-L923) · [crInput.ts:60–88,125–163](https://github.com/microsoft/playwright/blob/v1.51.1/packages/playwright-core/src/server/chromium/crInput.ts#L60-L163)

**A raw CDP implementation needs explicit frame routing.** Attach a private session to the pinned page. Set `Target.setAutoAttach(autoAttach=true, flatten=true, waitForDebuggerOnStart=false)` there, handle attach/detach, and repeat on child targets if deeper frames are supported. Map the stage iframe owner to its `frameId`. An in-process child uses its parent's session. An OOPIF has a child session. Preserve that distinction on process swaps. V1 can restrict interaction to the immediate presented document, including when it is an OOPIF. [Target.pdl:235–255](https://github.com/ChromeDevTools/devtools-protocol/blob/cc9d57b1934a83436915b583659c41ae107ad3bb/pdl/domains/Target.pdl#L235-L255) · [DOM.pdl:167–170](https://github.com/ChromeDevTools/devtools-protocol/blob/cc9d57b1934a83436915b583659c41ae107ad3bb/pdl/domains/DOM.pdl#L167-L170) · [crBrowser.ts:585–599](https://github.com/microsoft/playwright/blob/v1.51.1/packages/playwright-core/src/server/chromium/crBrowser.ts#L585-L599)

**Capture should continue during ordinary input.** tvpipe starts a current-tab `getDisplayMedia()` stream and encodes frames with WebCodecs. A second client's input changes what Chromium paints without starting another capture or changing the selected surface. I would expect an in-frame click, edit or scroll to appear in the existing stream. A top-level document navigation destroys the capture script's context. tvpipe detects it and injects again, so a short visual gap is expected. Avoid debugger pauses, screencasts, viewport overrides and tab switching. A pushed-frame counter establishes sender activity. Verifying a particular interaction on the receiver requires observing the changed content. [headless.js:21–39](https://github.com/mitsuhiko/tvpipe/blob/v0.2.0/crates/tvpipe/src/browser/headless.js#L21-L39) · [capture.js:187–209](https://github.com/mitsuhiko/tvpipe/blob/v0.2.0/crates/tvpipe/src/browser/capture.js#L187-L209) · [headless.rs:744–763](https://github.com/mitsuhiko/tvpipe/blob/v0.2.0/crates/tvpipe/src/browser/headless.rs#L744-L763) · `present/tvpipe.py:174–182,263–266`.

## 3. Accessibility and Green CPU cost

| Read path | What it buys | Cost control |
| --- | --- | --- |
| CDP `Accessibility.getFullAXTree({frameId, depth})` | Chromium's native roles, names, states and tree structure. For an OOPIF use its owning session. For an in-process iframe obtain the owner's frame ID with `DOM.describeNode` and pass it in the parent session. Omitting the ID on the stage reads the wrong root. | **Recommended for the public snapshot.** Use a one-shot read and export selected fields. A depth cap bounds depth only. Also cap returned nodes and bytes. Persistent `Accessibility.enable` keeps IDs stable and carries a documented ongoing performance cost. V1 does not need stable AX IDs. [Accessibility.pdl:194–241](https://github.com/ChromeDevTools/devtools-protocol/blob/cc9d57b1934a83436915b583659c41ae107ad3bb/pdl/domains/Accessibility.pdl#L194-L241) |
| Playwright `frame.locator("body").aria_snapshot()` | Simplest prototype. Returns YAML for a DOM subtree with computed roles and names. Works at the bridge's minimum Playwright version. A unique named landmark can narrow the read. | The injected implementation walks descendants and computes accessible names. Trimming YAML afterward saves transport bytes but leaves that walk intact. Older versions can include input values. The `depth` and AI-ref options require 1.59, while the bridge permits 1.51. [Locator API](https://playwright.dev/python/docs/api/class-locator#locator-aria-snapshot) · [ariaSnapshot.ts:38–166](https://github.com/microsoft/playwright/blob/v1.51.1/packages/playwright-core/src/server/injected/ariaSnapshot.ts#L38-L166) · `app/requirements.txt:10`. |

Blink may update style/layout, attach a full AX context and update the AX cache *before* walking to the requested depth. Even a read without explicit enable can create a context. Use a short-lived CDP session for the snapshot and detach it in a finally block on success, failure or timeout. Keep the sender’s Playwright connection alive. [Chromium tree read, lines 234–257](https://github.com/chromium/chromium/blob/main/third_party/blink/renderer/modules/accessibility/inspector_accessibility_agent.cc#L234-L257) · [AX context cleanup, lines 675–697](https://github.com/chromium/chromium/blob/main/third_party/blink/renderer/modules/accessibility/inspector_accessibility_agent.cc#L675-L697)

The Green lifecycle run measured about **646–725 MiB of active container memory** with inline pages. The render CPU study used an M4 guest and projected A55 demand. Neither measures Chromium AX reads on the Green. A one-shot read is a burst of renderer work, serialization and IPC. Tree width, accessibility-name computation and request rate matter. A small response limit cannot bound all renderer work. There is no measured basis here for a CPU percentage or for claiming one API is faster. See `docs/live-browser-lifecycle.md:3–25`, `docs/spike-s2.md:34–40,70–85`.

On the Green, compare the same page with snapshots disabled, then at one read per second, at the shipping 1080p/10 fps. Include a small form and a wide dashboard. Record cold/warm p50 and p95 latency, cgroup CPU delta, memory, pushed/dropped frames and audio continuity. Keep the page animation identical across runs. Separately test input with a visible counter and verify its value on the TV. The app defaults and existing measurements are in `app/config.yaml:19–26`, `present/browsers.py:83–105` and `docs/live-browser-lifecycle.md:3–7`.

## 4. Security boundary

- **Identity and transport.** Use the existing HA admin-only MCP/REST proxy and the app's internal bearer check. Keep the CDP endpoint private to the bridge. The app uses host networking, so verify the *actual* Chromium listener is loopback-only in the release image. Never return its port, WebSocket path, session IDs or profile. The proxy forwards a shared internal credential. Apply limits per TV and across the bridge, since the app does not receive a trusted HA user ID. See `custom_components/atv_bridge/http.py:9–15,26–48,79–97`, `server.py:184–189`, `app/config.yaml:5–8`.
- **Document scope.** Bind actions to TV, sender generation, captured target, stage revision and committed document generation. Uploaded content must stay under the active bundle's canonical `/c/<id>/` URL. A live page must stay at a destination authorized by the presentation. Refuse browser-internal/error URLs, other local stage/control routes, nested frames, popups and detached documents. Authorize any allowed redirect before granting interaction. Invalidate on document navigation, hide, disconnect, sender restart or transport change. Page ID alone is insufficient when the same bundle is shown twice. See `stage.py:136–144,168–181,210–215`, `tools/__init__.py:425–444`.
- **Limit what the agent can request.** Accept closed action schemas, literal names and a small role/key allowlist. Omit raw selectors, coordinates, browser shortcuts, URL navigation, file pickers, uploads, downloads, clipboard, cookies, network hooks and arbitrary JS. If a read is missing, add a named operation with typed arguments and a fixed implementation. An isolated JS world still has DOM and web APIs. A length limit, timeout or expression filter does not make user-supplied JS read-only.
- **Browser egress is a separate limit.** Even a permitted click can submit a form, cause a download or run page code that makes requests. The existing live probe follows redirects. The wrapper uses `--no-sandbox`, and tvpipe bypasses CSP and grants local-network permissions for its capture connection. Scope checks prevent *continued control* after navigation. They cannot undo a request already sent. If arbitrary, untrusted pages must have hard file/network isolation, enforce it outside the page before enabling interaction for them. Restrict browser filesystem access and use a default-deny egress boundary with explicit destinations for the stage, active bundle/assets, tvpipe capture socket and approved live backends. Cover redirects, resolved IPs, workers and WebSockets while preserving authorized LAN dashboards. This is additional work beyond the two MCP tools. See `app/build/chromium-wrapper:1–2`, `live.py:97–122`, `stage.py:260–281`. [headless.rs:467–477,488–515](https://github.com/mitsuhiko/tvpipe/blob/v0.2.0/crates/tvpipe/src/browser/headless.rs#L467-L515)
- **Data and limits.** Return visible semantic labels and selected states. Drop AX value, description, URL and backend identifiers. Treat all page text as untrusted content. Avoid credential fields and suppress detailed browser exception strings. Preserve the audit policy of recording argument names and outcomes. Start with one in-flight operation per TV, one snapshot/s, four actions/s with burst four, a global snapshot concurrency of one, a two-second action deadline and bounded text/output. These are proposed defaults to tune on hardware. See `state.py:94–109`, `tools/public.py:24–31,90–112`.

## 5. Minimal tool contract and implementation

Both tools use the existing result envelope and fleet `tv` selector. Require the `page_id` from `tv_show`. One action per call keeps ordering and delivery errors explicit.

| Tool | Input | Result in `data` |
| --- | --- | --- |
| `tv_page_snapshot` | `tv?`, `page_id`, optional `depth` (default 6, max 10) | `page_id`, opaque `document` token, `mode` (iframe/direct), ordered nodes with depth, role, name and selected states, plus `truncated`. Start with 200 nodes / 16 KiB. Tokens are freshness checks, scoped to this TV. |
| `tv_page_action` | `tv?`, `page_id`, `document`, tagged action. `click(target)`, `type(target,text)`, `press(target,key)`, or `scroll(dy,target?)`. A target is a unique `{role,name}` pair from the document. | `page_id`, action, and delivery status. A completed browser action means dispatched. A subsequent snapshot verifies the intended page change. No automatic second snapshot or implicit submit. |

Use strict exact role/name matching in the approved frame. Return `ambiguous_target` or `target_missing` without dispatch. Resolve a specific element in this document for the action so locator retry cannot transfer input to its replacement. For `type`, replace up to 2,048 characters in a visible editable text field with Playwright fill. Reject file/password fields. For `press`, focus the verified target and accept a short enum such as Enter, Space and arrow keys. For `scroll`, clamp the signed delta to one viewport and use a fixed document/element scroll helper. An unlabeled canvas control or duplicate role/name can remain unsupported in v1. After a timeout or navigation during dispatch return `delivery_uncertain`; never replay a mutation automatically.

- Add `present/interaction.py` for document binding, snapshot projection, target checks and actions. Factor the frame-selection logic out of `present/tvpipe.py:108–162` and reuse it from document verification. Keep lifecycle invalidation with the sender. Include the revision in stage DOM and WS ready messages so a repeated bundle cannot acknowledge an earlier show. See `data/stage.html:32–58`, `stage.py:168–179,233–245`.
- Register the schemas in `tools/contract.py:92–100,156–159` and handlers on `PublicTools`. MCP listing and shared dispatch already derive from this contract. Reuse the per-TV lock and acquire the stage lock in the existing order. Recheck sender generation immediately before dispatch and after completion because background recovery can bypass tool serialization. See `mcp_http.py:118–140`, `fleet.py:396–410,437–449`, `tools/public.py:90–148`, `tools/__init__.py:419–421,505–515`.
- Give page tools a browser-only path on success **and on error**. The generic dispatcher can wake the receiver, handle system prompts and perform a native tvOS accessibility read. Skip those paths for page tools and reuse cached screen metadata if the public envelope needs it. See `tools/public.py:38–49,121–138,192–206`. Keep `tv_remote` and `tv_look` scoped to the TV.

**Estimated effort is 3–5 engineer-days** for a trusted-page mirror MVP, including target binding and snapshots (1–2 days), tool integration and input (1 day), and browser/Green tests (1–2 days). Estimate hard browser egress isolation separately. Test an opaque-origin bundle, a cross-site OOPIF, direct fallback and top-level navigation, same-bundle re-show, overlapping/pending frames, a duplicate-URL popup, two TVs, restart during input, and auto fallback to MP4. On the Green, verify that the captured tab shows the action result, audio continues, and hide returns Chromium process count to zero.

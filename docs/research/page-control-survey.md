# Lightweight browser interaction for the Apple TV Agent Bridge

**November 20, 2026.** Give agents six operations on the page already showing on the TV. Start with a compact accessibility snapshot that includes controls, headings and status text. Let agents act on short element refs and request another observation when they need one. A recipe agent can read “Step 2 of 6,” click “Next,” and check for “Step 3 of 6” without knowing the page’s HTML.

## Six operations for the bridge

| Proposed MCP tool | Contract |
| --- | --- |
| `tv_page_observe` | Return the current view. Optional `scope` ref reads one region or control. Optional literal `find` searches the whole document with a few lines of context. A cursor continues a truncated result. |
| `tv_page_click` | Activate one visible, enabled control by ref. Handles buttons, links, tabs, checkboxes and custom controls with accessible roles. |
| `tv_page_fill` | Replace the value of one editable field by ref. Return its resulting state with sensitive values masked. The agent can press Enter separately to submit. |
| `tv_page_select` | Select a native option by ref to the select and an exact option value. Observing that control returns its option labels and values. Custom menus use click or press. |
| `tv_page_press` | Send one page key to the target ref. Allow Enter, Space, Escape, Tab, Shift+Tab, arrows, Home, End and PageUp/PageDown. Keep browser shortcuts outside the schema. |
| `tv_page_scroll` | Scroll the document or a referenced scroll container one viewport in a named direction. Report whether it moved and whether it reached the edge. |

Reuse the existing `tv` routing rules and HA authorization. Resolve the current mirror’s Playwright page for that TV. For staged content, address the committed iframe with the matching `data-page-id`. That iframe can be cross-origin. For a live URL shown directly, use the main frame. The existing mirror verifier already makes this distinction. A recording fallback has no interactive surface on the TV and should return a clear error. [Mirror implementation](https://github.com/neekolas/ha-apple-tv/blob/0c49644774981ce5adc4174d5610c0a992e3df9f/app/atv_bridge_app/present/tvpipe.py) · [Presentation modes](https://github.com/neekolas/ha-apple-tv/blob/0c49644774981ce5adc4174d5610c0a992e3df9f/skills/apple-tv/content.md)

Keep `tv_show` as the URL and presentation entry point. For pages the agent authored, `tv_update` and `tv.state` already support semantic commands and reported state. Use the new six for ordinary pages with buttons, fields and status messages. `tv_look` remains useful when the question is what actually appeared on the receiver. Its accessibility items and optional PNG come from tvOS. A Chromium observation should work independently of tvOS screen pairing. [Bridge MCP contract](https://github.com/neekolas/ha-apple-tv/blob/0c49644774981ce5adc4174d5610c0a992e3df9f/docs/mcp-api.md)

### Observation and action replies

Return one text block in the existing MCP result envelope. Give refs to actionable nodes and scopeable regions. Keep accessible names, short visible text, field values and meaningful state such as focused, disabled, checked, selected or expanded. Retain a nearby group or row label when several controls share a name. Preserve headings, alerts and live status even when they have no action.

```text
page_id=p17 view=v4 title="Recipe" more=false
heading "Tomato soup"
status "Step 2 of 6"
e1 button "Previous"
e2 button "Next" focused
e3 checkbox "Keep screen awake" checked
```

This illustrative view is **174 UTF-8 bytes and 52 o200k_base tokens**, excluding the MCP envelope. Start with a budget of **2 KiB and 40 rows**, whichever comes first. Reserve room for focus, the active dialog, alerts and controls. Escape page strings and redact secret fields. If rows are omitted, set `more=true` and return a cursor. Apply the same cap to scoped reads and search results. Count bytes for enforcement and measure tokens with the actual client model. [tokenizer definition](https://github.com/openai/tiktoken/blob/main/tiktoken_ext/openai_public.py)

Require `page_id` and an opaque `view` token on mutations, including scroll. Bind refs to the TV, presentation, document and exact DOM node. Resolve and dispatch under the same presentation lock. A replacement, reload, detached node or invalid cursor should return `stale_view` with a request to observe again. Never silently retarget a matching label. Keep unchanged refs usable across reads within a view. Check visibility, enabled state and hit target before dispatch. PinchTab already ships a versioned ref check. [PinchTab ref protocol](https://github.com/pinchtab/pinchtab/blob/a62662027f233444c579c29fbe42ad90df0d5bc7/docs/reference/snapshot.md)

Return a short acknowledgement with the current view token and any observed focus, value or status change. A click acknowledgement means input was dispatched. For a delayed effect, the agent calls `observe(find="Step 3")` before retrying. Restrict targets to the presented content. Exclude the stage shell, other tabs, file inputs, arbitrary evaluation and raw CDP. For read-only page access, enforce the observe-only policy on the server, including its HTTP tool route. Enforce any configured destination policy on redirects and popups too, while allowing the LAN origin the operator chose to present. Canvas-only controls are the main coverage gap. Authors can expose a labeled button or a `tv_update` handler. [Page authoring guide](https://github.com/neekolas/ha-apple-tv/blob/0c49644774981ce5adc4174d5610c0a992e3df9f/skills/apple-tv/content.md)

## What agents actually use

- **UI tasks.** WebArena-Pro recorded five coding agents on 300 tasks each. Ref-based click ranked first for every agent, with 2,711–4,322 calls per agent. Navigation had 954–1,753, typing 820–1,399, and key presses 272–501. Text find reached 1,307. Screenshots ranged from 8–89, coordinate clicks from 59–166 and element drags from 4–20. These are invocation counts, including free observations. They support ref-first control and search for this UI workload. [WebArena-Pro, table 17](https://arxiv.org/pdf/2611.17955v1)
- **Live-site research.** I counted the tool field in all ten shards of WebdriverIO’s October 9 run, 100 tasks per setup. With default Playwright MCP, the agent used evaluate 660 times, navigate 655, snapshot 439, click 413 and find 371. With Stagehand’s code-oriented MCP it used run 2,097 times, snapshot 382 and screenshot 245. In the agent-browser shell traces, the literal commands get, eval, open and snapshot appeared more often than click. Shell commands can be batched, so occurrences and MCP calls have different denominators. For the bridge, scoped text reads cover a common reason to inspect a page without granting code execution. [October benchmark and step logs](https://github.com/webdriverio/benchmark/tree/8c63705737c78fc5ec67d8a59ede2920b0461a49/results/2026-10-09-run-37883072636)
- **Cost.** In that run, median whole-task tokens were 652k for Playwright MCP, 574k with automatic snapshots and codegen off, 354k for Stagehand’s code façade and 735k for agent-browser. These totals include cache reads and writes across turns. In Stagehand’s separate eight-task study, Playwright used 97k median tokens with defaults and 105k tuned. A shorter reply helps each read. The number of retries, calls and repeated context determines the task total. [Benchmark methods and versions](https://github.com/webdriverio/benchmark/blob/8c63705737c78fc5ec67d8a59ede2920b0461a49/README.md) · [Stagehand’s September measurements](https://www.stagehand.dev/blog/playwright-mcp-token-usage)

The remaining examples describe workflows that maintainers document or demonstrate. I found no public production frequency breakdown for each product.

## Upstream designs

### Microsoft Playwright MCP

The November repo identifies version 0.0.86. Its basic loop is snapshot or find → click, type, select or press → verify. Element tools accept a snapshot ref or a unique selector. A text snapshot is an indented, YAML-like list of roles, names and states, such as `- button "Next" [ref=e2]`. The two button lines in Microsoft’s test are 59 bytes and 25 o200k_base tokens before the response envelope. Tree size grows with the page. Explicit snapshots can be scoped by target or depth. Find returns matches and nearby lines. [Version](https://github.com/microsoft/playwright-mcp/blob/2337aff0213d28db41d3e3daf48cee19b3d0bd82/package.json) · [Snapshot fixture](https://github.com/microsoft/playwright/blob/a018f24a4fc76e2120d3b35d2415f1e5bd4b073e/tests/mcp/snapshot-mode.spec.ts) · [tokenizer definition](https://github.com/openai/tiktoken/blob/main/tiktoken_ext/openai_public.py)

In the current source, automatic `full` snapshots are written to a file and the action response links it. An explicit `browser_snapshot` returns content inline unless a filename is supplied. `--snapshot-mode none` suppresses automatic snapshots. A file link saves context for a colocated coding agent but is a poor observation for a remote HA client. Core already includes screenshots. `--caps=vision` adds coordinate click, down, drag, move, up and wheel. An image-capable model can use these on a canvas. Semantic refs remain available. [Response implementation](https://github.com/microsoft/playwright/blob/a018f24a4fc76e2120d3b35d2415f1e5bd4b073e/packages/playwright-core/src/tools/backend/response.ts) · [Tool and capability reference](https://github.com/microsoft/playwright-mcp/blob/2337aff0213d28db41d3e3daf48cee19b3d0bd82/README.md)

The README lists 24 core tools plus tabs. Names below omit the common `browser_` prefix.

| Purpose | Tools |
| --- | --- |
| Observe and inspect | `snapshot`, `find`, `take_screenshot`, `console_messages`, `network_request`, `network_requests` |
| Input | `click`, `drag`, `drop`, `hover`, `type`, `fill_form`, `select_option`, `press_key`, `file_upload`, `handle_dialog` |
| Page and lifecycle | `navigate`, `navigate_back`, `wait_for`, `resize`, `emulate_media`, `close`, `tabs` |
| Execute | `evaluate`, `run_code_unsafe` |

Optional groups include config, network routing, storage, DevTools, vision, PDF and testing. Read-only annotations describe individual tools. The advertised surface includes page JavaScript and server-process JavaScript. An isolated profile limits persistence. Origin allow/block lists apply to requests and explicitly exclude redirects. The allowed-hosts setting controls where the MCP server can be served. [Configuration and complete tool list](https://github.com/microsoft/playwright-mcp/blob/2337aff0213d28db41d3e3daf48cee19b3d0bd82/README.md)

### Google Chrome DevTools MCP

The basic UI loop is `take_snapshot(pageId)` → `click` or `fill` by UID → `press_key` or `wait_for`. The indented Chromium accessibility tree has rows like `uid=1_1 checkbox "checkbox" checked`. Use UIDs from the latest snapshot. Verbose mode includes more nodes, file output moves the tree out of context, and input tools default to omitting the follow-up snapshot. Coordinate click requires experimental vision. A documented production use is UI verification with snapshots, screenshots, computed styles and traces. [Full tool reference](https://github.com/ChromeDevTools/chrome-devtools-mcp/blob/bdecb63549a0b1a6d073fdf69ecc264bf46adda9/docs/tool-reference.md) · [Output fixture](https://github.com/ChromeDevTools/chrome-devtools-mcp/blob/bdecb63549a0b1a6d073fdf69ecc264bf46adda9/tests/formatters/snapshotFormatter.test.js.snapshot) · [UI verification case study](https://developer.chrome.com/blog/p2er-ui-verification-with-devtools-for-agents)

The actual `--slim` set is **navigate, evaluate, screenshot**. Clicks and field edits then depend on caller-supplied JavaScript. Full mode offers category switches, temporary profiles, `--javascript-evaluation=false`, file-navigation restrictions and URL-pattern allowlists on Chrome 149+. Disabling evaluation cuts the caller-code entry points. Pages still execute their own handlers when clicked. [Slim contract](https://github.com/ChromeDevTools/chrome-devtools-mcp/blob/bdecb63549a0b1a6d073fdf69ecc264bf46adda9/docs/slim-tool-reference.md) · [Configuration](https://github.com/ChromeDevTools/chrome-devtools-mcp/blob/bdecb63549a0b1a6d073fdf69ecc264bf46adda9/docs/configuration.md)

### Browser Use

The November Python package is 1.0.6. The local MCP server advertises `browser_exec`, `browser_screenshot`, `browser_login` and `browser_feedback`. Browser control lives in a persistent Python namespace. The old 0.x MCP action list would misdescribe this release. The harness guide teaches agents to filter Chromium accessibility nodes by role/name, read the backend node ID, click its box center and verify with a targeted page read. Helpers and page JavaScript also support indexed clicks, selectors, typing and navigation. [Browser Use and indexed click example](https://github.com/browser-use/browser-use/blob/ccbdb8095fbaf903c748880a600054a34c7b6191/README.md) · [Maintainer workflow](https://github.com/browser-use/browser-harness/blob/22ecf8545d67c474fa024643632d70af28b7fa0e/SKILL.md)

Observation is whatever text the Python cell prints, or a separately requested screenshot with optional maximum image dimension. Cell text is clipped at 12,000 characters plus a file pointer. Local managed-browser configs support allowed/prohibited domains. The MCP implementation explicitly runs supplied code in the server process with access to its files and environment. A four-tool inventory therefore grants much broader authority than this bridge needs. [MCP implementation](https://github.com/browser-use/browser-use/blob/ccbdb8095fbaf903c748880a600054a34c7b6191/browser_use/mcp/cli_mcp.py) · [Text limit](https://github.com/browser-use/browser-use/blob/ccbdb8095fbaf903c748880a600054a34c7b6191/browser_use/repl/session.py)

### Stagehand v4 and Browserbase MCP

**Stagehand SDK.** `observe(instruction)` returns candidate actions with a description, selector, method and arguments. `act` accepts either English or a previously observed action. Reusing the candidate skips another inference. `extract` can return schema-validated data. The internal observation is a hybrid accessibility tree. The caller can scope by CSS or XPath, ignore regions, or request one field. Output size follows the number of candidates or records, and the grounding model also consumes tokens internally. The docs demonstrate validating a candidate method, then filling credentials locally through its locator. Observe/extract support read workflows. The general SDK also exposes browser control. [Observe and validation](https://github.com/browserbase/stagehand/blob/4d72a87ff7615f160fc66ef917bbb68849a545f0/packages/docs/v4/basics/observe.mdx) · [Extraction](https://github.com/browserbase/stagehand/blob/4d72a87ff7615f160fc66ef917bbb68849a545f0/packages/docs/v4/basics/extract.mdx) · [Credential handling](https://github.com/browserbase/stagehand/blob/4d72a87ff7615f160fc66ef917bbb68849a545f0/README.md)

**Browserbase hosted MCP.** Six named tools cover `start`, `end`, `navigate`, `act`, `observe` and `extract`. Agents describe the target in English and can pass the session ID on every call. The docs demonstrate navigating and extracting one heading. Observation returns candidates and extraction returns requested data. The hosted reference publishes no fixed response-size cap. It requires a Browserbase API key and offers no caller-eval tool or documented read-only switch in this surface. A hosted session operates its own browser. The old self-hosted reference is archived. Stagehand’s separately benchmarked `run/snapshot/screenshot` façade exposes a different contract. [Hosted tools and session targeting](https://docs.browserbase.com/integrations/mcp/setup) · [Archive notice](https://github.com/browserbase/mcp-server-browserbase/blob/3e6f53461949037d5e65dd425da3ceb1263f11d6/README.md) · [Stagehand façade study](https://www.stagehand.dev/blog/playwright-mcp-token-usage)

### Vercel agent-browser

The native CLI keeps a browser open. The documented loop is `open` → `snapshot -i` → `click @e1` or `fill @e2` → read again. It also supports select, press, scroll, wait and targeted reads. CLI snapshots default to the full tree. Its stdio MCP defaults to a core tool profile and interactive-only snapshots. Rows contain role, name and ref. CSS, XPath, text and semantic locators are alternatives. Surviving DOM nodes retain their refs. If a node is replaced, unique role/name recovery can retarget the action. Ambiguous recovery fails. [CLI workflow](https://github.com/vercel-labs/agent-browser/blob/4b3ffa75deb59b7564c6aafbe60dc0b60b98c15a/README.md) · [Snapshot and ref semantics](https://github.com/vercel-labs/agent-browser/blob/4b3ffa75deb59b7564c6aafbe60dc0b60b98c15a/docs/content/docs/snapshots.mdx)

Compact output retains visible text and status. Interactive-only output drops static content, which would lose a recipe step or dashboard reading. Depth, CSS scope and `--max-output` bound a read. The security controls are opt-in. A domain allowlist, deny-by-default action policy, confirmations and content boundary markers are available. Core MCP includes eval. Use a trusted server policy to restrict it. [Security controls](https://github.com/vercel-labs/agent-browser/blob/4b3ffa75deb59b7564c6aafbe60dc0b60b98c15a/docs/content/docs/security.mdx) · [MCP profiles](https://github.com/vercel-labs/agent-browser/blob/4b3ffa75deb59b7564c6aafbe60dc0b60b98c15a/docs/content/docs/commands.mdx)

### BrowserMCP

The November server exports one `browser` tool with a command language. Its instructions encourage batching predictable actions, using `snapshot -i` or `find` to locate targets, then reading again after navigation. Click and fill accept refs, Playwright locators or CSS. Scroll can target a container. Press sends a key to the focused element. Snapshots use Playwright’s YAML-like rows. The interactive filter preserves headings, named landmarks and table cells. Reads default to 10,000 characters and can be raised to 75,000. [Agent workflow](https://github.com/BrowserMCP/mcp/blob/a51ddc4ee2210b102468a52b114e6f00e5bd206e/packages/mcp/src/commands/instructions.ts) · [Snapshot filtering](https://github.com/BrowserMCP/mcp/blob/a51ddc4ee2210b102468a52b114e6f00e5bd206e/packages/mcp/src/commands/snapshot.ts) · [Read budgets](https://github.com/BrowserMCP/mcp/blob/a51ddc4ee2210b102468a52b114e6f00e5bd206e/packages/mcp/src/commands/output.ts)

A loopback relay connects to the user’s signed-in Chrome after one-time code matching. The extension enforces Stop, excludes browser and extension pages, and respects Chrome’s incognito permission. The command language includes page eval. Raw CDP requires an extra capability. The server documents file access with the local user’s privileges. Pairing grants substantial authority even with only one MCP tool. [Pairing and tab controls](https://github.com/BrowserMCP/mcp/blob/a51ddc4ee2210b102468a52b114e6f00e5bd206e/README.md) · [Commands](https://github.com/BrowserMCP/mcp/blob/a51ddc4ee2210b102468a52b114e6f00e5bd206e/packages/mcp/src/commands/commands.ts) · [File access](https://github.com/BrowserMCP/mcp/blob/a51ddc4ee2210b102468a52b114e6f00e5bd206e/packages/mcp/README.md)

### Two 2026 approaches worth borrowing from

**PinchTab.** This local Go service exposes HTTP, CLI and MCP. Its documented loop is navigate, snapshot, click/type by ref, press a key, then snapshot or get text. Snapshots support compact rows, interactive filtering, CSS scope, diffs and a budget. Its 40-control fixture was 1,644 bytes compact versus 8,211 bytes in JSON. The project estimates 411 versus 2,052 tokens. A snapshot token lets the server reject refs from a superseded view. Bearer/session authentication and domain policy limit access. Eval, upload, downloads and cookie access are gated and off by default. [Formats and measured sizes](https://github.com/pinchtab/pinchtab/blob/a62662027f233444c579c29fbe42ad90df0d5bc7/docs/reference/snapshot.md) · [MCP workflow](https://github.com/pinchtab/pinchtab/blob/a62662027f233444c579c29fbe42ad90df0d5bc7/docs/guides/mcp-agents.md) · [Security defaults](https://github.com/pinchtab/pinchtab/blob/a62662027f233444c579c29fbe42ad90df0d5bc7/skills/pinchtab/TRUST.md)

**Chrome WebMCP.** Google introduced the early preview in February. A cooperating page registers named operations through JavaScript or annotated HTML forms. Agents discover a schema, call the operation with arguments and read its result. Payload size follows the operation’s schema and result. Google demonstrates booking and date selection. The page defines the executable handler and can request user confirmation. The `tools` Permissions Policy defaults to same-origin use. Headless support and adoption by arbitrary pages are limitations. For an authored TV page, the existing update/state contract already offers this direct path. [February announcement](https://developer.chrome.com/blog/webmcp-epp) · [Chrome API, permissions and examples](https://developer.chrome.com/docs/ai/webmcp)
